# Composable LeWM implementation plan

Reviewed `57588f3` against the two requested architectures. The implementation uses a single `LeWM` class and keeps the existing experiment entry points as configuration adapters during migration.

## What breaks today

| Seam | Finding | Required change |
| --- | --- | --- |
| Package and builders | `models/__init__.py` imports the missing `TCNEncodedAction`. `models/lewm.py` imports builders back from its partially initialized package and asks for the missing `heads` factory. Action and decoder entries are mostly strings that the factories call as constructors. `models/builders.py` still calls the removed `get_backbone`, passes legacy constructor arguments and imports `TimeAuxiliary` from its old module. Its attention and AE/VAE calls also pass an encoder positionally to a keyword-only factory. The legacy attention registrations still refer to a removed class and file. | Make the package registry point to actual constructors and assemble modules in `models/__init__.py`. Resolve obsolete registrations against the pre-refactor code before changing their behavior. |
| Model | `LeWM.__init__` builds a `decoder` while `forward` calls an undefined `predictor`. It mutates nested configs, copies freeze flags from the wrong slots, reverses the current and future latent names in its output and gives the full action result to predictors with incompatible signatures. | Inject built modules. Give each slot its own freeze policy. Normalize the predictor call and the output contract. |
| Engines | `MaskedEngine` references a missing injector, invokes zero masking without a mask and reverses the corrupted and clean views. `ForecastEngine` reaches for undefined encoder attributes and alternates between a tuple and a mapping. It can silently floor raw crop boundaries, and its default split can reach an unset crop in `_query_start`. | Return the same result type from both engines. Keep them responsible for view preparation and raw crop coordinates. |
| Blocks and encoders | `ResNetBlock` calls `list(stride)` for an integer. `StackedConv1dBlock` has the same problem for stride and dilation. `Conv1dSamePadding` preserves length at stride 2, contradicting encoder metadata. `Conv2dSamePadding` inherits `Conv1d` and creates weights with the wrong rank. Both basic encoder stacks iterate over `len(ks)` and `EncoderAction` passes the wrong positional arguments. | Fix argument normalization and true downsampling, use a real 2D convolution and construct the TCN using explicit keyword arguments. |
| Frequency predictor and mask action | Pointwise blocks use the unsupported keyword `kernel_size`. `FreqPredictorFiLM` uses the encoder width for the FiLM input and attaches the wrong output widths to two scales. The auxiliary action defaults to scalar `aux_channels`, discards its mask logits and resizes against the target latent. `TimePredictorFiLM` inherits `nn.Module` and passes predictor arguments to its constructor. | Use the auxiliary feature width and current token length. Return logits alongside the conditioning payload. Repair the shared time predictor variants used by existing configs. |
| Attention predictor | It reads `action.hiddent_dims`, unpacks dictionary keys as positional arguments, always takes the TCN branch for a nonempty type string and constructs `CrossAttention` without its required head. Default residual kernel normalization calls `list(5)`. Forward passes K in the Q slot. The diagonal mask sizes both axes from Q. | Give one module ownership of each projection. Call attention by named roles and validate Q/K/V dimensions before dispatch. Keep the reconstruction head outside attention. |
| Training and scoring | `Trainer` calls `model(x, mask=...)`, reads `latents`, and expects level metadata and training hooks. Losses read keys absent from the current forward result. `score()` miscalls `reconstruction_score_map`, reads absent output keys, can autocast and returns a format the scorer cannot consume. | Wire the trainer, criterion and scorer in the same change as model construction. Keep the scorer's `fused`, `levels` and `signals` format. |

The normal import and builder check stop at the missing action class. Isolated CPU probes reproduced the engine, ResNet, stride, TCN, 2D convolution and predictor errors above. A legacy-format synthetic batch exercised each existing LeWM loss independently, and `tests/verify_sigreg.py` passed.

## Shared interface

- `models/__init__.py` exposes registries for engines, feature extractors, actions, predictors, heads and score functions. Assembly in `models/__init__.py` copies configs before reading options, resolves widths and strides between slots, and passes initialized modules to `LeWM`. Builders bind scoring options to callable score functions. They validate which action payload each predictor accepts and which output domain the scorer needs.
- `models/lewm.py` owns `engine → encode views → action → predictor → optional head`, with `forward(x, mask=None, action=None)` and `score(x)` as normal entry points. `encode(x)` applies an optional backbone followed by the encoder. Both views use the same encoder in these presets. A backbone is an optional upstream feature extractor with its own weights and freeze policy. A feature extractor dedicated to the action or head can be injected into that module.
- Each engine returns `current_input`, `target_input`, raw half-open `current_range` and `target_range`, and optional input-resolution `mask_target`. Each action returns a predictor payload plus optional supervision outputs such as `mask_logits`. Declare the inputs that each action may read. The reconstruction action uses the current view and mask metadata. The guided action can read the observed future latent. Optional modules have role-specific defaults, such as a pass-through backbone or an empty action payload.
- Each predictor returns `predicted_latent[B,D,T_target]`. The head consumes that tensor and, when enabled for raw reconstruction, emits `recon[B,C,W_target]`. A raw head mirrors the effective feature path, including backbone downsampling and input channel count if a backbone is present. Keep exact target shapes and validate geometry with effective stride `S = S_backbone × S_encoder`.
- Expose `context["L0"] = current_latent`, `targets["L0"] = target_latent` and `predicted["L0"] = predicted_latent` to the latent criterion. Keep `latents["L0"]` as the clean/target encoder latent for existing trainer diagnostics. Expose the raw `recon` and its matching `target` only for a raw-output head. Also expose mask logits, aligned supervision, action diagnostics and target range. Keep trainer metadata and hooks, or migrate their callers atomically.
- Freeze parameters and keep the corresponding module in eval mode across `train()` calls. Where a frozen predictor or head has trainable upstream inputs, its operations must still propagate gradients to those inputs. Load pretrained feature-extractor weights strictly and independently of the downstream encoder. Load them before optimizer creation on new runs. Resume full runs from their own checkpoints.

## 1. Masked reconstruction with frequency FiLM

```text
MaskedEngine(x, mask) -> Xm[B,C,W], clean x[B,C,W], M[B,W]
encode(Xm) -> current_latent[B,D,T]              encode(x) -> target_latent[B,D,T]
AuxTimeAction(Xm, current_latent, M) -> token_input[B,D,T], FiLM[B,Da,T], logits[B,W]
FrequencyPredictor(token_input, FiLM) -> predicted_latent[B,D,T]
Optional raw head(predicted_latent) -> recon[B,C,W]
```

- Reuse `SubAnomalyMaskCollator` for the existing `{"input": M, "X_inj": Xm}` payload. Zero masking can use `{"input": M}` and produce `Xm = x.masked_fill(M[:, None, :], 0)`. The engine consumes the perturbation once. `target_input` remains the original window. A scoring call uses the observed window and self-proposed action without injecting a fresh perturbation. In that path the observed window is the residual reference.
- For the requested preset, the auxiliary convolution sees the masked input `Xm` and emits raw-time mask logits and features. The known mask supervises the logits and can teacher-force token placement. Keep it outside the logit and FiLM feature extractors so they can operate with the same inputs at score time. Keep a latent-input auxiliary adapter for older `TimeAuxiliary` weights and configs, where logits and targets both live on the latent grid.
- Convert the known raw mask to a token mask `m[B,T]` with an explicit rule. For stride-aligned inputs, max over each token span preserves short injections. Use the same token-span convention for score placement. The action returns `(1-m) * current_latent + m * learned_mask_token` and time-aligned FiLM features. Default to known placement in training and use the auxiliary's predicted probabilities for deployment-style validation and scoring. If prediction loss should update the mask-logit projection directly, train with a differentiable predicted-mask blend. The teacher-forced path updates the shared auxiliary trunk through FiLM and the logit projection through mask supervision.
- Align raw auxiliary features to the current latent time grid and resize again to each STFT neck scale inside FiLM. With neck widths `(w0,w1,w2)`, the three modulated activations have widths `(w1,w2,w2)`. FiLM projects from `Da` at each scale. iSTFT returns the original latent length `T`. Use explicit FP32 STFT and iSTFT, including casting the real and imaginary neck outputs before building the complex tensor. Validate the minimum supported latent length for the STFT padding and preserve odd/even transform lengths where supported.

## 2. Guided forecasting with a future-derived key

```text
ForecastEngine(x) -> Xcurrent[B,C,Wc], Xfuture[B,C,Wf], target range [a,b)
encode(Xcurrent) -> current_latent[B,D,Tc]
encode(Xfuture)  -> target_latent[B,D,Tf] -> TCNAction -> key[B,Hq,Tf]
History projections -> query[B,Hq,Tf], value[B,Hv,Tf]
Attention(Q=query, K=key, V=value) -> [B,Hv,Tf]
Output projection -> predicted_latent[B,D,Tf] -> optional raw head -> [B,C,Wf]
```

- Define crops in raw timesteps. Resolve the default half split once, reject empty, overlapping or stride-misaligned ranges, and validate the actual window passed on each call. Encode the crops separately so a noncausal backbone cannot carry observations across the split. Keep both raw offsets and their token equivalents available for positional encoding.
- Keep the requested future-derived K. The attention output has one position per query and each key indexes a value. A direct `Q,V = current_latent` assumes equal crop lengths. Use history-derived query and value projections onto `Tf` forecast slots, with a target-position signal for each slot. Start with explicit temporal alignment followed by channel projections, and keep the alignment local to this predictor. For 256 history steps, 128 future steps and stride 8, history encodes to 32 tokens, the guide encodes to 16, and Q, K and V each have 16 slots. Use length-preserving TCN keys, head-compatible channel widths and a final projection to `D`. Keep any attention mask shaped `[Tq,Tk]`, with explicit position semantics. A diagonal mask alone cannot make an observed-future key past-only.
- This preset predicts a future crop **conditioned on observations from that crop**. Its anomaly residual becomes available once the guide is available. Track it as a guided residual in experiment metadata. Future gradients flow through both the target operand of the latent loss and the TCN key. Changing the future guide with current latents fixed should change the prediction. Keep V history-derived to avoid a direct future-value copy.
- Keep finite action selection separate from the learned action module. An external planner supplies a candidate action or sequence to a predictor rollout and compares candidate costs. The LeWM paper uses the Cross-Entropy Method for planning over sampled action sequences. A finite action catalog is a repo-specific action representation. Implement that planner separately from the two trainable presets. [LeWorldModel paper, Appendix B](https://arxiv.org/html/2603.19312v3#A2)

## Loss routing

Start with L1 latent prediction for the new presets and keep the configured KL/MSE behavior for legacy runs. The existing symmetric KL applies softmax over channels, so per-token shared channel offsets are invisible to that objective. Check tensor ranks and exact pair shapes before any subtraction or broadcasting. The current LeWM L1 accepted a length-1 prediction against a length-8 target in a CPU probe.

| Term | Operands | Gradient path |
| --- | --- | --- |
| Latent prediction | `L1(predicted_latent, target_latent)`, equal `[B,D,T_target]` | Predictor, current encoder path and target encoder path with the existing no-detach convention. It also trains the mask token and auxiliary trunk through FiLM, or the guided TCN through K. |
| Current SIGReg | `SIGReg({"L0": current_latent})`, pre-action | Current encoder path. The statistic tests across the batch at each current token position. |
| Target SIGReg | `SIGReg({"L0": target_latent})` | Target encoder path. It works independently of current token length. These two regularizers act on the trainable representation after any frozen backbone. Use linear latent outputs in the new preset if the chosen final activation would restrict the representation to nonnegative values. |
| Mask supervision | `BCEWithLogits(mask_logits, mask_target.float())`, equal `[B,W]` for the new raw-input auxiliary | Mask projection and shared auxiliary trunk. Keep legacy MSE on sigmoid selectable for existing configs. The target is the synthetic mask. No supervised mask term for the guided preset. |
| Raw reconstruction | `L1(recon, target_input)`, equal `[B,C,W_target]` | Head and trainable upstream path in joint training. A head-only stage freezes the upstream modules. A raw head requires a positive raw-loss weight in the joint preset for it to learn. |

Compute `loss = w_pred*pred_loss + λ_current*sigreg + λ_target*sigreg_tgt + w_mask*aux_loss + w_raw*recon_loss`. Resolve each term from its named operands and weight. A positive weight requires its operands and an intentional gradient path. Skip disabled terms and retain stable scalar logging keys. Keep `pred_loss` as the latent prediction metric in both new presets, with `recon_loss` reported separately. Preserve existing phase-two criterion semantics through their adapters, including `RecCALoss` which also owns a second reconstruction branch and agreement loss.

## Scoring and migration order

1. Restore imports and builder entry points. Use `d139678` as the pre-refactor reference for removed classes and prior tensor behavior. Inventory the public builders and state-dict prefixes before changing them. Keep existing AE/VAE and Rec+CA experiments reachable while adding the two presets. Validate renamed keys and tensor shapes with real checkpoint fixtures before promising compatibility. Require a fresh run when tensor shapes or optimizer layouts cannot be migrated.
2. Fix block geometry and constructor contracts. Check width and length at every stage with unequal neck widths, `Da != D`, stride greater than one and an unequal-length crop. Verify causal TCN padding. If a TCN preset promises per-token causality during training, use normalization that works independently per token or disable normalization, since training BatchNorm aggregates across time. For masks, verify the clean target equals the input and the injected/zeroed current view matches the collator payload.
3. Implement the shared forward interface, then wire masked reconstruction, then guided forecasting. Verify current and target field meanings with distinct inputs. Use asymmetric crops and a changed-future-guide probe to expose swapped Q/K or ignored conditioning. Check that frozen modules retain eval mode and that their batch-normalization buffers and weights stay fixed across an optimizer step.
4. Route losses and test them independently before testing the weighted sum. Check a nonzero finite gradient on each expected trainable module. Check `pred_loss` reaches the two latent branches, the action token and FiLM, or the TCN action as applicable. FiLM's zero-initialized projections can block the auxiliary-feature gradient on the first prediction-only backward pass, so test that route after a projection update. Check that mask supervision reaches the logit projection and that raw reconstruction reaches the head. Confirm disabled terms do not require their operands.
5. Return score maps in FP32 with `fused`, `levels` and `signals` and restore mode after scoring. Pick the score domain explicitly. Latent scoring compares prediction against the target latent and maps token residuals to raw positions once. Raw scoring compares the head output to the observed target crop. For forecasts, use `target_input_range` and the existing `check_mask` placement so calibration sees the covered forecast span. Remove or bypass the old stride expansion wrappers for new models already returning input-resolution scores. Keep the existing train-only calibration and metric handoff.
6. Verify through the normal builder, trainer, validation, save/resume and score paths. Run the relevant `tests/verify_model_builders.py`, `tests/verify_lewm_frequency_steering.py`, `tests/verify_lewm_cross_attention*.py`, `tests/verify_lewm_reconstruction.py` and `tests/check_scorer_handoff.py` assertion scripts after the migration, adding targeted checks for the new unequal-crop and loss-routing cases. Finish with one short normal-entry smoke run per preset.
